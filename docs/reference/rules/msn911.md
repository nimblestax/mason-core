## What it checks

`MASON_DATABRICKS_CLI` names a Databricks CLI older than this Mason supports.

## Why

Each Mason release is tested with one Databricks CLI version and names the oldest it supports. An older CLI can deploy the same project differently, so Mason refuses it and runs nothing. A CLI that doesn't report its version is refused too.

## Example

`MASON_DATABRICKS_CLI` names a Databricks CLI at version 0.240.0. In a project, this fails:

```console
$ mason deploy --env dev
```

## Fix

Point `MASON_DATABRICKS_CLI` at the Databricks CLI version the diagnostic names, or unset it so Mason downloads its own.
