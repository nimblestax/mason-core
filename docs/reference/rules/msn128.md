## What it checks

`prod` uses the same workspace as another Environment. This is a warning, and `mason validate` still passes.

## Why

One workspace for every Environment works under every Naming Style, so a team can start on a single free workspace. The Environment is part of every catalog name, so Environments never share a table. But prod is then kept apart only by catalogs, each Environment's CI identity and their grants, not by a workspace boundary, and a grant set too wide reaches prod.

## Example

Write this file into the project `mason init` creates, and `mason validate` fails:

`mason.platform.yaml`:

```yaml
kind: platform
version: 2
name: shop
environments:
  dev:
    host: https://your-workspace.cloud.databricks.com
  prod: {}
naming:
  style: domain-catalogs
  layers:
    models: [gold]
domains:
  - sales
```

## Fix

Give prod its own `host` when you can. Until then, keep each Environment's CI identity and grants separate.
