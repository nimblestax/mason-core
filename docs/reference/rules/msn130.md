## What it checks

No Environment in `mason.platform.yaml` sets `role: development`.

## Why

Mason knows an Environment by its role, not its name. The Development Environment is where pull request Plans compare against, where Preview Environments live, and the workspace any Environment without a `host` uses. A project has exactly one, so Mason doesn't guess it from a name.

## Example

Write this file into the project `mason init` creates, and `mason validate` fails:

`mason.platform.yaml`:

```yaml
kind: platform
version: 2
name: shop
environments:
  dev:
    host: https://your-workspace.cloud.databricks.com
naming:
  style: domain-catalogs
  layers:
    models: [gold]
domains:
  - sales
```

## Fix

Add `role: development` to the Environment people develop in, such as `dev`.
