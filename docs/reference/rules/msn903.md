## What it checks

`MASON_DATABRICKS_CLI` names a Databricks CLI that Mason can't run.

## Why

Mason runs its own pinned Databricks CLI, which it downloads the first time it needs it. `MASON_DATABRICKS_CLI` points Mason at a CLI you installed yourself instead, for a machine that can't download one. The file it names doesn't exist, or this machine can't run it.

## Example

`MASON_DATABRICKS_CLI` is set to `/opt/databricks/databricks`, which doesn't exist. In a project, this fails:

```console
$ mason deploy --env dev
```

## Fix

Point `MASON_DATABRICKS_CLI` at the Databricks CLI's binary, or unset it so Mason downloads its own.
