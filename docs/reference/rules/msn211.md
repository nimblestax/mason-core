## What it checks

A Gold Model reads silver that has `keys` with `STREAM(...)`.

## Why

A stream reads only rows added since its last update. Silver with `keys` is written by upserts, which change and delete rows in place, so a stream from it fails in the pipeline's first update after a change. Read without `STREAM(...)`, the Gold Model is a materialized view, which Databricks refreshes incrementally where it can.

## Example

Write these files into the project `mason init` creates, and `mason validate` fails:

`domains/sales/sources/orders.yaml`:

```yaml
kind: source
version: 1
path: /Volumes/{env}_sales/bronze/landing/orders
format: json
silver:
  keys: [order_id]
  sequence_by: updated_at
```

`domains/sales/models/gold/fct_orders.sql`:

```sql
SELECT order_id, amount
FROM STREAM(sales.silver.orders)
```

## Fix

Read the table without `STREAM(...)`, as `FROM sales.silver.orders`.
