## What it checks

The Databricks CLI Mason downloaded doesn't match the checksum its release names.

## Why

Each Mason release names one Databricks CLI version and the checksum of each platform's archive. Mason downloads that archive from Databricks' GitHub releases the first time it needs the CLI. An archive that doesn't match was changed or cut short on the way, so Mason doesn't install it and runs nothing.

## Example

A proxy between you and GitHub changes the archive Mason downloads. In a project, this fails:

```console
$ mason deploy --env dev
```

## Fix

Run the command again. If it fails again, something between you and GitHub is changing the download: check your proxy, or point `MASON_DATABRICKS_CLI` at a Databricks CLI you installed yourself.
