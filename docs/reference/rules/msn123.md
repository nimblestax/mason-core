## What it checks

More than one Environment in `mason.platform.yaml` sets `default: true`.

## Why

Commands that read rather than deploy use the default Environment when `--env` is left out. With two defaults, Mason can't tell which one you mean, so it doesn't guess.

## Example

Write this file into the project `mason init` creates, and `mason validate` fails:

`mason.platform.yaml`:

```yaml
kind: platform
version: 1
name: shop
environments:
  dev:
    host: https://your-workspace.cloud.databricks.com
    default: true
  prod:
    default: true
naming:
  catalog: "{env}_{domain}"
  schema: "{layer}"
  layers:
    sources: [bronze, silver]
    models: [gold]
domains:
  - sales
```

## Fix

Keep `default: true` on one Environment and remove it from the others. With none, dev is the default.
