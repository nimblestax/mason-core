## What it checks

Two config files share a name in one Domain's Layer: in one folder, such as `orders.yaml` and `orders.yml`, or in two folders, such as `sources/erp/orders.yaml` and `sources/crm/orders.yaml`. Brickie reads either ending, and writes `.yaml`.

## Why

A config file's name is its table's name, so two files with one name would declare one table twice, and Brickie can't tell which one is meant. Folders inside `sources/`, `seeds/` or a model Layer's folder only group files, so they don't make two tables. The same name in two model Layers is two tables, such as `sales.gold.orders` and `sales.marts.orders`.

## Example

Write this file into the project `brickie init` creates, and `brickie validate` fails:

`domains/sales/sources/orders.yml`:

```yaml
kind: source
version: 1
path: /Volumes/{env}_sales/bronze/landing/orders
format: json
```

## Fix

Keep one of the files, and delete or rename the other.
