## What it checks

`BRICKIE_DATABRICKS_CLI` names a Databricks CLI that Brickie can't run.

## Why

Brickie runs its own pinned Databricks CLI, which it downloads the first time it needs it. `BRICKIE_DATABRICKS_CLI` points Brickie at a CLI you installed yourself instead, for a machine that can't download one. The file it names doesn't exist, or this machine can't run it.

## Example

`BRICKIE_DATABRICKS_CLI` is set to `/opt/databricks/databricks`, which doesn't exist. In a project, this fails:

```console
$ brickie deploy --env dev
```

## Fix

Point `BRICKIE_DATABRICKS_CLI` at the Databricks CLI's binary, or unset it so Brickie downloads its own.
