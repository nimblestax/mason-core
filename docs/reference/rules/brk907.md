## What it checks

The refresh failed because a row broke an Expectation whose `action` is `fail`.

## Why

An Expectation with `action: fail` stops the update when a row breaks it. Bronze is append-only, so the row stays there, and every refresh fails on it until the rule changes. Landing a corrected row doesn't remove the bad one.

## Example

A row in bronze has a negative `amount`, and the Source has an Expectation `amount >= 0` with `action: fail`. In a project, this fails:

```console
$ brickie deploy --env dev
```

## Fix

Correct the rule if the row is fine, or change its `action` to `quarantine` or `warn`, then deploy again. See [Recover from a failed refresh](../../guides/recover-from-a-failed-refresh.md).

## Principle

This Rule enforces [No row disappears silently](https://nimblestax.com/way/no-row-disappears-silently), from the Nimblestax Way.
