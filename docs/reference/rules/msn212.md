## What it checks

A name in a Gold Model's `depends_on` doesn't appear in its SQL exactly as written.

## Why

`depends_on` names the tables a Gold Model reads where Mason can't parse its SQL. Mason finds each name in the SQL text and replaces it with the real table for each Environment. A name that isn't in the text would declare a read the SQL doesn't make, and hide the one it does.

## Example

Write these files into the project `mason init` creates, and `mason validate` fails:

`domains/sales/models/gold/fct_orders.yaml`:

```yaml
kind: model
version: 1
sql: fct_orders.sql
depends_on:
  - sales.silver.orders
```

`domains/sales/models/gold/fct_orders.sql`:

```sql
SELECT order_id, amount
FROM STREAM(sales.silver.order)
WATERMARK ordered_at DELAY OF INTERVAL 1 MINUTE
```

## Fix

Write the name in the SQL exactly as it is in `depends_on`, or remove it from `depends_on`.
