## What it checks

More than one Environment in `brickie.platform.yaml` sets the same `role`.

## Why

A project has exactly one Development Environment and at most one Production Environment. Plans, Preview Environments and the approval gate each need to know which one Environment they mean.

## Example

Write this file into the project `brickie init` creates, and `brickie validate` fails:

`brickie.platform.yaml`:

```yaml
kind: platform
version: 2
name: shop
environments:
  dev:
    host: https://your-workspace.cloud.databricks.com
    role: development
  test:
    role: production
  prod:
    role: production
naming:
  style: domain-catalogs
  layers:
    models: [gold]
domains:
  - sales
```

## Fix

Keep the role on one Environment and remove it from the others. Any Environment without a role is an ordinary stage.
