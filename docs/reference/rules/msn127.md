## What it checks

A file sits directly in a Domain's `models/` folder, or in a first folder under it that isn't a model Layer in `naming.layers.models`.

## Why

A Gold Model's Layer is the first folder under `models/`, so `domains/sales/models/gold/fct_orders.yaml` is `sales.gold.fct_orders` and the path reads as the Logical Name. A file with no such folder has no Layer, and a misspelt folder would put a table in a schema nobody expects, so Mason doesn't guess.

## Example

Write these files into the project `mason init` creates, and `mason validate` fails:

`domains/sales/models/fct_returns.yaml`:

```yaml
kind: model
version: 1
sql: fct_returns.sql
```

`domains/sales/models/fct_returns.sql`:

```sql
SELECT order_id
FROM sales.silver.orders
```

## Fix

Move the file into a folder named after a model Layer, which the diagnostic lists. To add a Layer, add it to `naming.layers.models` in `mason.platform.yaml`.
