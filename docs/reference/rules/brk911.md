## What it checks

`BRICKIE_DATABRICKS_CLI` names a Databricks CLI older than this Brickie supports.

## Why

Each Brickie release is tested with one Databricks CLI version and names the oldest it supports. An older CLI can deploy the same project differently, so Brickie refuses it and runs nothing. A CLI that doesn't report its version is refused too.

## Example

`BRICKIE_DATABRICKS_CLI` names a Databricks CLI at version 0.240.0. In a project, this fails:

```console
$ brickie deploy --env dev
```

## Fix

Point `BRICKIE_DATABRICKS_CLI` at the Databricks CLI version the diagnostic names, or unset it so Brickie downloads its own.
