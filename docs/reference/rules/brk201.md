## What it checks

SQL reads a table that isn't in the project.

## Why

Brickie knows every table a project makes: each Source's bronze and silver tables, each Seed's table and each Gold Model's table. SQL reads them by Logical Name, such as `sales.silver.orders`, so Brickie can check every read before a deploy and point it at the right catalog in each Environment. A read it can't find is a typo, or a table nothing in the project makes. A table name without its Domain and Layer that isn't a CTE is reported too, because Brickie can't tell which table it means.

## Example

Write this file into the project `brickie init` creates, and `brickie validate` fails:

`domains/sales/models/gold/fct_orders.sql`:

```sql
SELECT order_id, amount
FROM sales.silver.order
```

## Fix

Declare a Source, Seed or Gold Model with this name, or correct the Logical Name.

## Principle

This Rule enforces [Code names tables logically; Brickie resolves the environment](https://nimblestax.com/way/code-names-tables-logically), from the Nimblestax Way.
