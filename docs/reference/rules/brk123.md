## What it checks

More than one Environment in `brickie.platform.yaml` sets `default: true`.

## Why

Commands that read rather than deploy use the default Environment when `--env` is left out. With two defaults, Brickie can't tell which one you mean, so it doesn't guess.

## Example

Write this file into the project `brickie init` creates, and `brickie validate` fails:

`brickie.platform.yaml`:

```yaml
kind: platform
version: 2
name: shop
environments:
  dev:
    host: https://your-workspace.cloud.databricks.com
    role: development
    default: true
  prod:
    default: true
naming:
  style: domain-catalogs
  layers:
    models: [gold]
domains:
  - sales
```

## Fix

Keep `default: true` on one Environment and remove it from the others. With none, the Development Environment is the default.
