## What it checks

SQL reads a real table name, which names one Environment, instead of its Logical Name.

## Why

A real table name such as `dev_sales.silver.orders` names one Environment's catalog, so the same SQL would read dev data in prod. A Logical Name such as `sales.silver.orders` names no Environment, and Brickie points it at the right catalog in each.

## Example

Write this file into the project `brickie init` creates, and `brickie validate` fails:

`domains/sales/models/gold/fct_orders.sql`:

```sql
SELECT order_id, amount
FROM dev_sales.silver.orders
```

## Fix

Use the table's Logical Name, which the diagnostic gives. If no table in the project has that name, declare a Source, Seed or Gold Model for it.

## Principle

This Rule enforces [Code names tables logically; Brickie resolves the environment](https://nimblestax.com/way/code-names-tables-logically), from the Nimblestax Way.
