## What it checks

A Gold Model reads a Seed, or a Gold Model that doesn't stream, with `STREAM(...)`.

## Why

A stream reads only rows added since its last update. A Seed, and a Gold Model whose SQL reads no `STREAM(...)`, are materialized views, which Databricks may recompute in full on any refresh, so it refuses a stream from one. A stream may read silver without `keys`, a Quarantine table, or a Gold Model that streams. See [How Brickie reads a gold model's SQL](../../concepts/how-brickie-reads-a-gold-models-sql.md).

## Example

Write these files into the project `brickie init` creates, and `brickie validate` fails:

`domains/sales/seeds/countries.yaml`:

```yaml
kind: seed
version: 1
file: countries.csv
columns:
  code: STRING
```

`domains/sales/seeds/countries.csv`:

```csv
code
AU
```

`domains/sales/models/gold/fct_orders.sql`:

```sql
SELECT code
FROM STREAM(sales.silver.countries)
```

## Fix

Read the table without `STREAM(...)`, as `FROM sales.silver.countries`.
