## What it checks

A `kind` isn't one Brickie knows.

## Why

Brickie checks each file against its Kind's schema. A misspelt `kind` has no schema, so nothing in the file can be checked. `brickie schema` reports this Rule too when it's asked for a Kind that doesn't exist, and exits 2, because the mistake is on the command line.

## Example

Write this file into the project `brickie init` creates, and `brickie validate` fails:

`domains/sales/sources/orders.yaml`:

```yaml
kind: sauce
version: 1
path: /Volumes/{env}_sales/bronze/landing/orders
format: json
```

## Fix

Use one of the Kinds: `model`, `platform`, `seed` or `source`. `brickie schema <kind>` prints a Kind's fields.
