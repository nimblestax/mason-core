## What it checks

With `--platform`, a catalog the project's tables need isn't in the Environment's workspace, or the identity Mason signs in as can't see it.

## Why

Mason makes tables, views and pipelines, and never catalogs or schemas: those belong to whoever runs the platform, so the same tool never both creates and grants them. `mason init` lists every catalog and schema to create. A deploy into a catalog that isn't there fails halfway through, so `mason validate --platform` checks first.

## Example

dev's workspace has no catalog `dev_sales`. In a project, this fails:

```console
$ mason validate --platform
```

## Fix

Create the catalog with the schemas the diagnostic lists, or grant the identity `USE CATALOG` on it.
